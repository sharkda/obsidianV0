### 🔴 Rows 1 and 2 did not actually fix it — there was a second asker

**I only found this because I ran the app.** Deleting the startup ask in `Municipal+Loc` closed one caller. A fresh install still put the dialog on screen, and the log said exactly why, two lines apart:

```
Municipal+Lifecycle  33  resumeForForeground()  ▶️ app → active: resuming GPS
Municipal+Loc        80  requestLocationPermission()  current :0 !
```

`resumeForForeground()` calls `startUpdateLocation()`, which **falls through to requesting permission when it is not authorized**. That runs on the `.active` scene phase — which happens at launch. So the dialog came back by a second route, with none of our new code involved.

Now guarded: `if locAuthorized { startUpdateLocation() }`. **Returning to the foreground is a moment to resume, never to first ask.**
