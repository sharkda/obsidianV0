claude: **Yes — and your version is better than both options I offered.** It is also closer to shipping than it looks, because **the map screen already does step 1.** `NbsScreen.wire0()` calls `municipal.requestLocationPermission()` on `.onAppear` (`NbsScreen.swift:973`). The check-then-ask you are describing is in the code today; it just never gets to run first.

**What actually beats it to it.** `hootowlApp.init()` builds `Municipal.shared` (`hootowlApp.swift:95`) → `wire0()` sets `locationMan.delegate = self` (`Municipal.swift:241`) → iOS immediately calls back with the current status → `.notDetermined` → `requestWhenInUseAuthorization()` (`Municipal+Loc.swift:31-33`). That is inside the **App's `init()`**, before any view exists. So the dialog is already spent by the time any screen could ask with context.

**So the required change is one deletion, not a feature.** Remove the request from the `.notDetermined` case (keep the log). Startup then asks for nothing, and the first ask the user meets is the map's — which is exactly your point 1. Nothing else has to move for that to be true.

> [!warning] One thing in your plan that will not work as written, and it is worth knowing before we build it
> **`assessedCoverage()` checks denied *before* it looks at the destination** (`Municipal+Coverage.swift:210-220`):
> ```swift
> if status == .denied || status == .restricted { return .denied }
> guard let point = effectiveCentre else { return .locating }
> ```
> So if a user declines and we fall back to a substitute location, **`coverage` stays `.denied` forever** and every screen stays blocked — the fallback would set a destination that nothing reads. The fix is small: only short-circuit on denied when **no destination is set**. Then your fallback works everywhere for free, because `effectiveCentre` already prefers the destination over the GPS fix.

**The fallback you want already exists, under another name.** What the app uses outside the active zone is not a simulation — it is `Destination`, and `setDestination(Destination(name: 台北市, coord: Municipal.taipeiCentre))` is **台北車站 / Taipei Main Station** (`Municipal+Coverage.swift:108`). `CoverageNoticeView` already offers it as a one-tap button in the `.outside` branch (lines 159-170). The `.denied` branch, by contrast, is a hard dead end today — its only action is **Open Settings** (lines 151-157). **So your idea 1 is mostly: give `.denied` the escape hatch `.outside` already has.** Same button, same call, one more `case`.

**Two notes on the wording, because both affect how it reads to a user:**

1. **Do not call it a simulation.** The parking data at 台北車站 is completely real and live — only the *centre point* is substituted. "Simulated" invites "so the numbers are fake?", which is the one thing we never want anyone to think about this app. Say the place: *「未開啟定位時，我們會以台北車站為中心顯示車位。」*
2. **Ask once, then stop asking.** Your *"every time that page loads"* works for the **first** ask, but iOS shows its own dialog **only once per install** — after a decline it never appears again, no matter how often we call it. So a custom explainer sheet on every map load would nag people with something they cannot act on. Recommend: explainer + ask on the **first** map load (`notDetermined` only), and after a decline show the quiet fallback card instead — which is the `.denied` card above, now with the 台北車站 button on it.

**Point 2 — onboarding screen 3.** With the startup ask gone, screen 3 becomes the honest pre-primer it was written to be: it explains the benefit, the button asks, and the system dialog appears **on the tap**. No code change needed beyond the deletion — it starts working by itself. Worth keeping for exactly the reason it was written: people who have read why say yes far more often than people ambushed at launch. Nothing is lost if you would rather not: a user who skips screen 3 simply meets the ask on the map instead.
