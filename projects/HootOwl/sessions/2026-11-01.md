## 1 — the keyboard window ate the tab bar

Jim hit it live. The screenshot showed a lone floating `Done` button **with no keyboard under it** — so a field held focus with nothing on screen to say so.

**Two faults compounded.** The keyboard's accessory bar lives in its own window pinned to the bottom of the display, exactly where the auto-hidden tab bar returns; it swallows every tap meant for the tab bar. And the field **could not let go of focus at all**, because `@FocusState` does not reach a `TextField` inside `ToolbarItem(.principal)` — UIKit hosts it in the navigation bar, outside the view's focus scope.

That second part is what explains five months of survival: the screen had **two** escape routes added for exactly this (`Done`, `.scrollDismissesKeyboard`) and **both were no-ops**. Jim's own words settled it — *"the input text box never loses the focus no matter what we do."*

Fixed with `endEditing(true)` across every window, called from the pill, from a tab change, and from the screen's own handlers. `2464fe5`.

> [!warning] My first attempt was wrong and I let him test it blind
> I used `sendAction(#selector(resignFirstResponder))` and told him to try it. **The simulator was running an 08:03 build; the fix landed at 08:57** — he was testing the old binary. Check what is actually installed before asking anyone to verify. Since then: build, install via `simctl`, confirm the symbol is in `hootowl.debug.dylib`, *then* ask.

## 2 — E-12 was the worst bug on the board

`IdWgs.longitude` is `Int(wgs84.longi)`. Measured against the shipped fences, **both hulls collapse to the same two lattice points** — one vertical line segment. Every edge then has `edgeX == 0`, the cross product reduces to `±pointX`, and the test returns `true` for **the whole 121°–122°E strip at any latitude on Earth**.

**The "masked by the 1 km tolerance" line was backwards.** `isInServiceArea` tests `convexEnclosing` *first* and returns `true` on a hit — the broken test short-circuits the correct one, so the tolerance never ran.

Fixed by doing the arithmetic in real degrees. Validated against `MunicipalFence.encloses(_:)`, the correct ray-casting test already in the same file: **131 of 47,291 grid points disagreed before, every one a false "covered"; 0 of 314,721 after.** `300b8d7`. Script kept at [[e12-fence-truncation-check.py]].

## 3 — subscribing told nothing

`Transaction.updates` does **not** deliver a transaction returned directly by the `purchase()` that created it. Both purchase screens only logged in `.onInAppPurchaseCompletion`, so the tier relay and the ad toggle never fired.

**A D-01 blocker:** the subscription *is* ad removal, so a banner that stays means the product does not exist and the Store description is false.

It hid behind a second omission — the transaction was never `finish()`ed, so it replayed at the next launch and relaunching "fixed" it. `1b83b72`, confirmed by Jim.

## Also shipped

**D-02** (2026-10-27) — the 40.6% of car parks with no live count now say so in both languages. Measured: Taipei 7.9%, New Taipei **69.4% and not falling**. `7cebf96`.

## Lessons, written to [[patterns/swift-patterns]]

- `Transaction.updates` does not cover your own purchase, and `finish()` is what stops the bug hiding
- `@FocusState` does not reach a `TextField` inside `.toolbar`
- truncating a coordinate to `Int` destroys a polygon; validate a geometric predicate against a second implementation over a grid
